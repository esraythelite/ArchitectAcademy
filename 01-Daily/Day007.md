# Day 007 — Query Use Case & Read Path

Date: 21 September 2026

## Goal

Implement the read path for the Onboarding aggregate and retrieve an existing
onboarding from PostgreSQL through the Application and Infrastructure layers.

## Use Case

Retrieve an onboarding by its identifier.

GET /api/onboardings/{id}

HTTP GET
    ↓
OnboardingController
    ↓
GetOnboardingByIdHandler
    ↓
IOnboardingRepository
    ↓
OnboardingRepository
    ↓
EF Core
    ↓
PostgreSQL
    ↓
Onboarding Aggregate
    ↓
GetOnboardingByIdResult
    ↓
HTTP Response

The handler retrieves the aggregate through IOnboardingRepository.
The Domain aggregate is not returned directly from the API. This prevents the external API contract from becoming coupled directly to the
Domain model.
Domain Aggregate
      ↓
Application Result DTO
      ↓
HTTP Response

Testing

Added unit tests for:

Existing onboarding returns a result.
Missing onboarding returns null.

Added integration tests for:

Create onboarding and retrieve it by ID.
Unknown ID returns 404 Not Found.
Returned values match the persisted onboarding.

The integration tests use Testcontainers with a real PostgreSQL instance.

Key Lessons
Domain models should not automatically become API contracts.
Not-found is a normal application outcome, not necessarily an exception.
Repository abstractions can support both command and query use cases.
EF Core can reconstruct Value Objects using configured value converters.
Integration tests should verify persistence in both directions.
Add abstractions only when the problem justifies them.
