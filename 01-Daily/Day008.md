# Day 008 — State Transition & Domain Command

Date: 23 September 2026

## Goal

Implement an application command that loads an existing Onboarding aggregate,
executes domain behavior, and persists the resulting state transition.

## Use Case

Verify an onboarding identity.

Started -> IdentityVerified

## Architecture Flow

HTTP
-> Application Command
-> Repository
-> Domain Aggregate
-> Domain Behavior
-> Unit of Work
-> PostgreSQL


## Testing

Added unit tests for:

- Existing onboarding transitions from `Started` to `IdentityVerified`.
- Missing onboarding returns `null`.
- Unit of Work is called only when a valid aggregate exists.

Added integration tests for:

- Existing onboarding can be verified.
- Verified status is persisted to PostgreSQL.
- Unknown onboarding returns `404 Not Found`.
- Verifying an already verified onboarding returns `409 Conflict`.

## Persistence Behavior

The aggregate is loaded as a tracked EF Core entity.

Repository.GetByIdAsync()
        ↓
Tracked Onboarding Aggregate
        ↓
VerifyIdentity()
        ↓
Status changes
        ↓
UnitOfWork.SaveChangesAsync()
        ↓
SQL UPDATE

Key Lessons
State transitions belong inside the Domain aggregate.
Application handlers orchestrate behavior; they should not manipulate domain state directly.
Domain invariants protect aggregates from invalid transitions.
EF Core change tracking can persist aggregate mutations without an explicit Update.
Expected state conflicts can be translated into HTTP 409 Conflict.
